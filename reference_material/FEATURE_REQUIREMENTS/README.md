# FEATURE_REQUIREMENTS — Intake Instructions

**Put per-feature requirement documents here.** One file per feature is ideal (e.g. `search.md`, `notifications.md`).

A good feature requirement answers:

- What can the user do?
- What data does it need (inputs, outputs)?
- Who can use it (guest / signed-in)?
- What happens on error, empty, or offline?
- Does it need device permissions (camera, notifications, location…)?
- Does it have store-policy implications (payments, user-generated content, age sensitivity…)?

Each registered feature lands in `docs/00_PRODUCT/FEATURE_BACKLOG.md` with a status of **proposed → approved → implemented → tested → released**, and triggers the change-control updates listed in `AGENTS.md` §11.
